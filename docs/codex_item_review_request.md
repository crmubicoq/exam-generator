# 문항 품질 교차 검수 요청 (Codex)

## 1. 목적과 검수 방식
이 툴이 AI로 출제한 평가문항을 **출제 전문가 입장에서 독립적으로 검수**해 달라. 출제와 1차 검증은 다른 AI(Claude·Codex)가 했으므로, 이번 검수는 사람 검수 전 교차 확인이다. 문항 오류는 다른 팀 서비스에 그대로 나가므로 엄격하게 본다.

- **읽기 전용**: 파일을 수정하지 않는다.
- **LLM 호출 금지**: 출제 파이프라인(`python -m exam_gen.cli run`)을 실행하지 않는다. 비용이 들고 결과가 바뀐다.
- **판단 근거**: 원고 PDF와 아래 기준 문서만 쓴다. 원고에 없는 상식으로 판단하지 않는다. 다만 "원고 밖 상식으로 다른 답을 우길 여지"는 지적한다.

## 2. 검수 대상
| 항목 | 위치 |
|---|---|
| 원고(샘플 교재 17~42쪽) | `input_17-43.pdf` (PDF 1쪽 = 책 17쪽) |
| 개선 후 출제 문항 | `projects/샘플_Claude_개선/items.sqlite` — `items` 테이블의 `data` 열(JSON). Claude Sonnet 5.5로 출제, 통과 43문항(난이도 보충 14문항 포함) |
| 개선 전 출제 문항(비교용) | `projects/샘플_Codex_테스트/items.sqlite` |
| 기준 문서 | `문항 출제 전문가_지침.txt`, `평가문항 출제 유의사항.docx`, `엑셀_출력 형식(양식).xlsx` |
| 출제 규칙(프롬프트) | `exam_gen/llm/prompts/generate_system.j2` |

문항 JSON 읽는 법은 아래와 같다. `status`가 `auto_pass`·`warn`·`approved`인 문항만 검수하고, `manual`(자동 검증 탈락)은 참고만 한다.
```python
import sqlite3, json
rows = sqlite3.connect("projects/샘플_Claude_개선/items.sqlite").execute("select data from items").fetchall()
items = [json.loads(r[0]) for r in rows]
# 주요 필드: key, type(mcq/ox/short), difficulty(실제 난이도), difficulty_target(목표), stem, statements(조합형),
#           choices[{text,is_true}], answer, short_variants, explanation,
#           evidence[{target, quote, is_true, trap_note, match{label(책 쪽수), level}}], source_pages
```
원고 텍스트는 `pymupdf`로 읽는다. `evidence[].match.label`이 책 쪽수이고, PDF 인덱스는 '쪽수 − 17'이다.

## 3. 문항마다 볼 것
| # | 항목 | 기준 |
|---|---|---|
| 1 | **정답 정확성** | 원고 기준으로 정답이 맞는가. 정답이 둘 이상이 될 여지는 없는가. **가장 중요하다.** |
| 2 | 근거 일치 | 참인 진술·정답·해설의 사실이 `evidence` 인용문과 원고에서 확인되는가. 근거 쪽수가 맞는가. |
| 3 | 함정의 타당성 | 거짓 보기·X 문항이 원고 기준으로 확실히 틀렸는가. 바꾼 수치가 원래 범위에 포함되어 참이 되지는 않는가. |
| 4 | 이의 제기 여지 | 원고 밖 상식·실무 경험으로 다른 답을 우길 수 있는가. 단서 문구("일반적으로", "가장 거리가 먼")가 필요한가. |
| 5 | 변별력 | 원고를 공부하지 않은 사람이 상식이나 보기 형태만으로 정답을 고를 수 있는가. 조합형은 거짓 진술 하나만 알면 풀리는가. |
| 6 | 난이도 | `difficulty`(최상·상·중·하)가 실제 사고 수준과 맞는가. 루브릭은 `exam_gen/spec/criteria.yaml`의 `difficulty_rubric`이다. |
| 7 | 지침 형식 | 선다형 발문이 질문형('…것은?')인가. 문어체(~이다/~한다)인가. 단답형 괄호 뒤에 조사 힌트가 없는가. 진위형 O 해설이 지문을 반복하지 않는가. '원고'·쪽수·절 번호가 노출되지 않았는가. |
| 8 | 조건·주체 | 주체·대상·상황이 빠지지 않았는가. '이 시기'처럼 문항 밖을 가리키는 지시어가 없는가. 일부 단계만 물으면서 전체 단계를 밝히지 않은 경우는 없는가. |
| 9 | 지엽성 | 학습목표와 관련된 중요 내용인가. 사례 속 사소한 수치나 고유명사를 암기하게 하지는 않는가. |
| 10 | 해설 | 해설만 읽어도 정답과 그 이유를 바로 알 수 있는가. 옳은 것 고르기 문항은 틀린 보기의 이유를 쓰는가. |
| 11 | 문장 | 맞춤법·띄어쓰기·주술 호응·용어 통일 |

## 4. 전체에 대해 볼 것
- **원고 전반 출제**: 26쪽 전체에 고르게 나왔는가. 특정 쪽에 몰리거나 빠진 곳은 없는가.
- **중복**: 판단 포인트가 사실상 같은 문항이 있는가.
- **분포**: 난이도·유형·정답 위치(①~④)·O/X 비율이 지침과 출제 옵션(난이도 최상5·상15·중60·하20 %, 유형 선다50·진위30·단답20 %, 옳은 것 고르기 20 : 옳지 않은 것 고르기 80)에 맞는가.
- **개선 전후 비교**: 개선 전 프로젝트(`샘플_Codex_테스트`)에서 지적된 문제가 줄었는가. 지적된 문제는 발문 비질문형 12/13, '원고' 노출 12, 실제 난이도 '하' 쏠림(27문항 중 20), 상식으로 걸러지는 오답 6, 조합형 지름길 1이다. 같은 집계를 `python -m exam_gen.quality_report 샘플_Codex_테스트 샘플_Claude_개선`으로 볼 수 있다. 자동 등급(특히 '변별력' 72%)은 검수 AI의 경고를 그대로 센 값이므로, 그 지적이 타당한지도 판정해 달라.
- **출제 규칙 자체의 문제**: 반복되는 결함이 프롬프트(`generate_system.j2`)나 검증 코드(`exam_gen/validate/rules.py` 등)의 규칙 누락에서 오는지, 고칠 규칙을 제안한다.

## 5. 보고 형식
**(1) 문항별 표** — 문제가 있는 문항만 적는다.

| 문항 키 | 심각도 | 항목(3절 #) | 문제 | 근거(원고 쪽·문장) | 수정안 |
|---|---|---|---|---|---|

심각도는 다음 기준으로 매긴다.
- **치명**: 정답 오류, 복수 정답, 원고와 다른 사실
- **높음**: 이의 제기 여지 큼, 상식으로 정답이 보임, 조건 누락
- **중간**: 난이도 불일치, 지침 형식 위반, 해설 부족
- **낮음**: 문장·표기

**(2) 요약**
- 검수한 문항 수와 심각도별 건수
- 문제없음 문항 수
- 문항 30개 기준으로 그대로 서비스에 내보낼 수 있다고 판단하는 문항의 비율

**(3) 규칙 개선 제안**: 반복되는 결함과, 그것을 막기 위해 바꿀 프롬프트 문구나 검증 규칙. 상위 5개까지.

추정이 섞인 판단은 "추정"이라고 표시한다.
