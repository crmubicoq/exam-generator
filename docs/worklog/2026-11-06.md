## 3. 담당자 PC 설치 후 피드백 6가지 (오후)
- 사용자가 v1.0.0을 담당자 PC와 다른 팀원 PC에 설치했다. 피드백 6가지를 받아, 제안안대로 반영했다(사용자 승인).
- **1. 새로 설치했는데 Claude가 이미 로그인됨**
  - 원인: 패키지에는 로그인 정보가 없다(v1.0.0 ZIP 두 개를 직접 확인). Claude 로그인은 윈도우 사용자 폴더 `.claude`에 저장되어, 그 PC에서 전에 Claude Code 등으로 로그인한 계정을 그대로 쓴다.
  - 대응: 처음 실행하거나 계정이 바뀌면 **"이 PC는 ○○ 계정으로 출제합니다"** 확인 창을 띄운다(`ui._account_check`). [맞습니다]를 누르면 `account_confirmed`에 이메일을 남기고, [다른 계정으로 로그인]도 할 수 있다.
- **2. 검수 완료·미검수 알림**
  - 승인·삭제·일괄 승인 뒤 남은 검수가 0이면 **검수 완료** 창을 띄우고 [출력으로 이동]을 둔다.
  - 출력 화면에 들어올 때 미검수 문항이 있으면 **알림 창**을 띄운다(프로젝트마다 세션당 한 번).
  - 공통으로 `review_ops.pending_counts`를 쓴다.
- **3. 엑셀 난이도 열**: 제출 양식 칸(A~P) 밖인 **Q열**에 '난이도(담당자 판정 우선)'를 넣었다. 기출처럼 난이도 정보가 없는 문항은 빈칸이다.
- **4. 원고 근거 새 창에 해설**을 추가했다.
- **5. 수정 후 AI 재검증 생략(민감)**
  - 이유를 설명했다: 사람이 고친 내용이 정답 유일성·함정 모순을 깰 수 있다. 문항 오류는 서비스 사고다.
  - 사이드바 AI 설정 → **검수 설정**에 '수정 후 AI 재검증 없이 승인 허용'을 두었다. 기본은 꺼짐이다.
  - 켜면 사람이 고친 문항(`llm_stale`)에만 [AI 재검증 없이 승인]이 나온다. 조건은 세 가지다.
    - 무료 검사(G1·G2·G3·G6) 재통과
    - "책임지고 승인" 체크
    - 검수자 이름
  - 기록 방식
    - `validation.human_override`(내용 해시)를 남긴다. `integrity.has_override`가 있으면 승인과 납품 출력을 허용한다.
    - 다시 고치면 해시가 달라져 무효가 된다.
    - `llm_skipped`로 'AI 검증 생략' 대기열과 품질 리포트에 남고, 경고와 엑셀 검증 메모에 "수정 후 AI 재검증 생략 — 검수자 ○○ 확인"을 남긴다.
  - **발견해서 함께 고친 문제**: '생략한 AI 검증 실행'이 통과 문항을 자동통과·경고로 되돌려 **이미 승인한 문항의 승인을 풀 수 있었다.** 승인 당시 내용 그대로면 승인을 유지하게 했다. 탈락하면 수동확인으로 승인이 풀린다.
- **6. 멈춤 버튼**
  - 출제 진행 화면의 [중지]를 진행률 바로 옆으로 옮겼다.
  - 품질 리포트의 '생략한 AI 검증 실행'은 뒤에서 실행한다(`review_ops.start_verify_job`). 진행률과 [중지]가 있고, 묶음 단위로 멈추며, 다시 실행하면 남은 문항부터 한다.
  - 한 문항 AI 재검증은 짧아서(30초~1분) 멈춤 대신 소요 시간 안내를 넣었다.
- 테스트 `test_skip_reverify_override_flow`를 추가했다. 확인한 것은 다음과 같다. 테스트 94개 통과.
  - 고친 뒤 승인 차단, 이름 필수, 사람 책임 승인과 출력 포함
  - 생략 대기열, 엑셀 Q열
  - 나중 검증 후 승인 유지, 다시 고치면 무효
- 사용 매뉴얼(7·8·9·10·11·14절), 변경 내역('다음 버전(준비 중)'), README를 고쳤다.
- 버전 번호는 패키징 요청 때 올린다. 기능 추가이므로 v1.1.0으로 한다.
