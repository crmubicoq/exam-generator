## 2. 시연 피드백과 처리
1. **새 프로젝트를 만들어도 이전 프로젝트에 머묾** → 고침.
   - 목록이 새 프로젝트로 바뀌고 원고 등록으로 이동한다.
   - 원인: 사이드바 선택 상자가 이전 값을 유지했다.
2. **차시가 무엇인지** → 교육 과정의 회차·단원이라고 설명했다.
   - 담당자는 처음에 삭제를 원했으나, 용어가 헷갈렸던 것이고 기능은 편리하다고 해서 유지했다.
3. **난이도 기준이 프로젝트별인지** → 공통뿐이었다. 담당자 요청으로 **프로젝트 전용 기준**을 추가했다(아래 4절).
4. **출제 중 다른 화면·프로그램 사용** → 가능하다고 답했다. 출제는 검은 창(서버) 안의 별도 스레드에서 돈다. 검은 창 닫기·종료·절전만 안 된다.
5. **비율 옆 문항 수 표시** → 고침.
   - 난이도·유형 칸 아래에 '→ N문항'을 표시한다.
   - 세부 옵션에는 '선다형 53문항 중 옳은 것 11 · 옳지 않은 것 42', '조합형 5문항'을 표시한다.
6. **가·나·다 항목이 나뉘어 나오는지**
   - ㄱㄴㄷㄹ 진술은 원래 줄이 나뉘어 나온다.
   - 사례 블록 발문(100문항 중 16개)은 엑셀 말고는 줄바꿈이 사라졌다. 검수 화면·근거PDF·시험지PDF·이의신청 화면에서 유지하게 고쳤다.
7. **중복 판단 기준, 진위형↔단답형 중복** → 기준을 설명했다.
   - G6: 단어 겹침·판단 포인트 유사도로 0.72 이상은 탈락, 0.58 이상은 경고. 같은 유형·같은 근거 줄이면 탈락.
   - 최종 풀 점검: AI가 같은 원리 묶음을 경고한다.
   - 유형이 달라도 판단 포인트가 같으면 G6에서 걸린다.

## 3. 원고 등록 ③ 개선 (담당자가 순번·원고 쪽수를 헷갈림)
- 범위 지정을 **원고에 인쇄된 쪽수**(시작 쪽·끝 쪽 선택)로 바꿨다. 여러 파일이면 파일을 먼저 고른다.
- 순번·원고 쪽수·차시·제외 설명을 화면에 바로 보이게 넣었다. 표 열 도움말도 달았다.
- **차시 자동 제안**(`exam_gen/ingest/chasi_detect.py`, AI 사용 없음)
  - 무엇을 찾나: 본문의 번호 붙은 큰 제목(제N절·N장·Chapter·N차시).
  - 제목으로 보는 조건: 본문보다 큰 글씨이거나 페이지 첫 줄. 번호가 차례로 이어지는 첫 등장만 본다.
  - 제외하는 것: '제1절을 마치며', 본문 참조, 부록의 반복 제목.
  - 원고를 올리면 자동으로 적용한다. ③에 제안표와 [이 안으로 다시 나누기]가 있다.
  - 실제 원고에서 제1~5절(4·29·78·158·213쪽)을 정확히 찾았다.
  - 시연 프로젝트의 기존 차시는 20~28쪽이 2차시로 잘못 들어가 있었다. 프로젝트 자체는 고치지 않았다.
- **제외 이유** 열을 넣었다.
  - '자동: 글자가 적음(N자, 기준 80자 미만)', '자동: 목차 페이지', '직접 제외' 중 하나다.
  - 새 원고는 이유를 기록한다. 기존 프로젝트는 글자 수·목차 여부로 짐작한다.
  - 시연 프로젝트 제외 43장 = 자동 7장 + 직접 36장(머리말·부록·참고문헌).
- 차시를 바꾸면 이미 출제된 문항의 차시도 맞춘다(`sync_item_chasi`). 엑셀 A열이 어긋나지 않는다.

## 4. 프로젝트별 난이도 기준
- `difficulty_policy.py`
  - 공통 기준: `data/difficulty_policy.json`
  - 프로젝트 전용 기준: `projects/<프로젝트>/difficulty_policy.json`. 있으면 공통 대신 쓴다.
  - `use_common`은 전용 기준을 `.bak`으로 백업한 뒤 지운다.
- 전용 기준을 쓰는 곳: 출제(generator), AI 검수(review_llm), 엑셀 검증리포트, 출제 옵션 점검표와 기준 펼침. 출제 옵션의 기준 펼침은 원래 기본안만 보여 주던 것도 고쳤다.
- 난이도 기준 화면
  - '고칠 기준'에서 이 프로젝트 전용 / 공통을 고른다.
  - 전용 기준을 처음 만들 때는 공통 기준을 복사해서 시작한다.
- 데이터 내보내기·가져오기에 공통 기준 파일을 넣었다. 그동안 빠져 있었다.
- 문항의 `gen.difficulty_policy`는 이제 '공통·임시·기본안'처럼 범위를 포함한다.
