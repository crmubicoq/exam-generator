# 08. 개발 로드맵

원칙: 각 단계는 **원예기능사 실제 자료로 돌려서 기존 납품본과 비교**하며 끝낸다. 한 단계 = 한 PR 정도 크기.

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| S0 | 리포 골격 | 폴더 구조, CLI 뼈대(`run options.json`), config/scenarios.yaml, 테스트 환경 |
| S1 | Phase 0 사전 준비 | OCR 감지, footer PNG 생성, 페이지 매핑 규칙 저장, 단원별 페이지 범위, 기출 Excel 로드 |
| S2 | 근거 PDF 모듈 (기존 자산 이식) | 원예 기존 q_data로 근거PDF 재생성 → 30/30 매핑, 기존본과 시각 비교 동일 |
| S3 | planner + choice_builder | 시나리오 B로 30슬롯 생성, 분포 기준 전부 충족(단위 테스트) |
| S4 | Generator + Decider (LLM) | 슬롯 1개 → 문항 1개 JSON, 근거 매칭 통과, 실패 시 재생성 3회 |
| S5 | Validator | 근거 L1~L4, 표현정확도, 기출회피, 품질6 → 문항별 validation 필드 |
| S6 | 전체 실행 + 리포트 | 30문항 end-to-end, 검증 리포트, 검수형 정지점 3개 |
| S7 | 출력물 | Word 출제풀(기존 양식), 단답 변환본, 메일 초안 |
| S8 | 자동형 모드 + 중단 조건 | 4개 중단 조건 테스트 |
| S9 | (확장) 웹 UI / 팀 서버 배포 | 옵션 폼, 정지점 승인 화면 |

## Claude Code 첫 지시문 (S0)
```
docs/ 폴더의 01~08 문서와 CLAUDE.md를 먼저 읽어줘.
읽은 뒤 바로 코드를 쓰지 말고, 04_아키텍처_제안.md의 폴더 구조로 S0(리포 골격)를 만드는 계획을
파일 목록과 함께 보여줘. 내가 확인하면 그때 생성해줘.
```

## S2 지시문 예시
```
reference/samples의 원예 30문항 Word에서 q_data.json을 추출하는 스크립트를 먼저 만들고,
docs/06_근거PDF_구현자산.md 코드를 src/etest_agent/output/evidence_pdf.py로 모듈화해줘.
결과 PDF의 문항별 하이라이트 개수를 표로 보여주고, 0개인 문항이 있으면 멈춰서 알려줘.
```
