# 담당자 메일 공유 시 정해야 할 사항

담당부서에 시연·공유 메일을 보낼 때 함께 묻고 정할 항목이다. 생각나는 대로 추가한다(사용자 요청 2026-10-30).
결정되면 '결정' 칸에 날짜와 내용을 적고, 반영한 위치(코드·문서)를 남긴다.

## 1. API 키 사용 여부
- **현재**
  - 담당자 협의(2026-10-23)에 따라 앞으로 1~2개월은 **Claude 구독 로그인**으로 출제한다.
  - 구독 사용량에서 차감되고 별도 청구는 없다. 다만 한 번에 많이 출제하면 사용 한도에 걸려 잠시 멈출 수 있다.
- **정할 것**: 운영 단계에서 어떤 방식을 쓸지.
  - 구독 계정
  - **API 키**(회사 계정, 사용한 만큼 청구)
  - 사내 LiteLLM
- **참고 (실측 기반 추정)**
  - 난이도 보정 출제를 켠 100문항 실측(2026-10-30, 105문항 출제·AI 호출 528회)에서 SDK가 보고한 환산 비용은 약 65달러, **문항당 약 0.6달러**다.
  - 같은 방식이면 300문항(여유 15% 포함 345문항)은 **약 200달러**로 추정한다. (예전 추정 문항당 0.3달러는 보정 출제 전 값)
  - 토큰 사용량은 2026-11-04부터 기록한다. 다음 출제부터 프로젝트 관리 → 출제 이력에서 볼 수 있다.
- **함께 확인할 것**
  - API 키를 쓴다면 누가 발급·관리하는가.
  - 원고를 어떤 외부 AI 서비스까지 보내도 되는가(보안 정책).

## 2. 문제 난이도 기준 정책
- **현재**
  - 받은 기준 문서(출제 전문가 지침, 출제 유의사항, 스킬가이드)에는 **비율만** 있다. 하·중·상·최상 각각의 정의는 없다.
  - 담당자 협의(2026-10-23)로 정한 것은 두 가지다.
    - 최상 = 자격시험 수준 실무 사례형
    - 비율 = 최상 5 · 상 15 · 중 60 · 하 20
  - 지금 프로그램의 단계별 정의와 판정 방법은 **개발 중에 임시로 작성**한 것이다.
    - 정의: `exam_gen/spec/criteria.yaml`
    - 판정: `exam_gen/llm/prompts/review_system.j2`
- **확인된 사실 (2026-10-28~30)**
  - AI 검수는 출제 의도보다 **한 단계 낮게** 판정한다.
    - 상으로 낸 문항의 약 94%가 '중'으로 판정된다.
    - 최상 사례형의 약 93%가 '상'으로 판정된다.
  - Codex 블라인드 교차 판정도 29문항 중 22개(76%)가 같았다. 상으로 낸 문항은 Codex도 대부분 '중'으로 봤다.
    - 즉, 문항이 실제로 의도보다 쉽다.
    - 다만 최상 경계에서는 우리 검수가 조금 엄격하다.
- **정할 것**
  1. 담당부서에 **공식 난이도 정의(지침)**가 있는가. 없으면 정해 줄 수 있는가.
  2. **최상의 기준**: '자격시험형 실무 사례 문항'이면 최상으로 볼지, 판단이 두 단계 이상 이어져야 최상인지.
  3. **비율을 무엇 기준으로 맞출지**: 출제 의도(지시한 난이도)인지, 검수 판정 난이도인지. 지금은 판정 기준으로 맞추도록 '난이도 보정 출제'를 만들어 두었다.
  4. (선택) 경계 문항 몇 개를 보여 주고 "상인가 중인가"를 확인해, 판정 예시로 고정한다.
- **원칙(사용자 2026-10-30)**: 난이도는 사람마다 판단이 다를 수 있다. Claude·Codex가 '중'이라 해도 출제 담당자는 '상'으로 볼 수 있고, 그 반대도 있다. **기준은 담당부서가 정한다.** 그때까지 난이도 규칙(정의·출제 방법·판정 방법)은 바꾸지 않는다. Codex 제안 3가지(상 사례 필수, 최상 두 기준이 결론을 바꿈, 조합형 최소 판정 집합)도 보류한다.
- **제안할 방법 — 담당자 직접 판정**
  - 실제 문항 10~15개를 AI 판정을 숨기고 보여 준다. 하·중·상·최상이 고루 섞이게 하고, 경계 문항을 포함한다.
  - 담당자가 난이도를 직접 매긴다.
  - AI 판정과 비교해 두 가지를 정한다.
    - ① AI 판정 기준 보정: AI가 담당자보다 낮게 보는지, 높게 보는지.
    - ② 담당자가 생각하는 상·최상 예시를 출제 지침에 넣는다.
  - '난이도 보정 출제'의 비율표는 지금은 AI 판정 기준이다. 담당자 판정이 나오면 그 기준으로 다시 만든다(프로그램 구조는 그대로 두고 숫자만 바꾼다).
- **대응 순서(2026-10-30 합의)**: 담당자가 해 줄 수 있는 만큼 받는다.
  1. 지침 문서가 있으면 대시보드 **관리 → 난이도 기준**에 넣고 '확정'한다.
  2. 지침이 없으면 **기준안(블룸 인지 수준: 하=기억, 중=이해, 상=적용, 최상=분석·종합/자격시험형)**을 보여 주고 승인·수정만 받는다.
  3. 글로 정하기 어려우면 문항 10~15개에 **검수 화면 '담당자 판정 난이도'**로 직접 매겨 달라고 한다. 그 판정이 곧 기준이 된다.
  4. 아무것도 받지 못하면 '임시 기준안'으로 운영한다. 출제 전 점검표와 엑셀 검증리포트에 '임시 기준안(담당자 확인 전)'이 표시된다. 이후 검수 때 담당자 판정이 쌓이면 난이도 보정이 그 기준으로 맞춰진다.
- **새로 받은 기준표 (사용자 2026-11-03)** — 담당부서 확정본인지 먼저 확인한다. 확정본이면 공통 기준에 '확정'으로 넣는다.
  - 표 항목: 묻는 능력(용어 확인 → 개념 이해 → 비교·구분 → 결합·적용), 근거 범위(한 문장 → 한 단락 → 한 단원 내 여러 곳 → 2개 이상 단원·표 결합), 선다 형식(패턴 A~D), 단답 형식(용어 1·2·3개 / 조합·결합 판단), 함정 수, 허용 함정, AI 대응, 목표 정답률, 권장 비중(하 20 · 중 40 · 상 25 · 최상 15)
  - 이 표대로 하려면 정해야 할 것
    1. **단답형 '용어 2개·3개'**: 지금 정답은 용어 1개다. 2~3개면 엑셀 정답 칸·채점기준·자동채점 형식이 바뀐다. 문항을 올리는 시스템이 이 형식을 받는가?
    2. **최상 'AI 대응 — 교재 없이 AI가 틀려야 함'**: 지금 독립 풀이(G4)는 원고를 보고 맞히는지 본다. 이 기준을 쓰려면 '원고 없이 풀어서 틀리는지' 검사를 새로 넣는다(문항당 AI 호출 1회 증가).
    3. **진위형(OX)** 난이도 기준이 표에 없다.
    4. **함정 수**를 무엇으로 셀지: 4지선다의 그럴듯한 오답 수인가, 조합형의 거짓 진술 수인가.
    5. **목표 정답률**은 실제 시험 뒤에만 확인할 수 있다 — 출제 기준이 아니라 시험 후 분석 기준으로 쓸지.
    6. **권장 비중**: 지금 기본값(최상 5 · 상 15 · 중 60 · 하 20)보다 상·최상이 20% → 40%로 두 배다. AI가 의도보다 낮게 판정하는 경향(100문항 시험 최상 0)이 있어 목표에 못 미칠 수 있고, 출제 시간이 늘어난다.
- **프로젝트별 기준(2026-11-03 반영)**: 과정마다 난이도가 다를 수 있다는 담당자 의견에 따라, 관리 → 난이도 기준에서 **공통 기준**과 **프로젝트 전용 기준**을 따로 둘 수 있다. 과정별 기준이 있으면 그 과정 프로젝트에만 넣는다.
- **결정**: (미정) — 담당자가 지침 유무를 확인하기로 함(2026-10-30). 기준표 확정 여부 확인 중(2026-11-04)

## 3. 사용 인원과 계정 (2026-11-04 추가)
- **현재**: 담당부서 2명이 각자 PC에 휴대용 패키지를 설치해 쓴다. PC마다 처음 한 번 `Claude_로그인.bat`으로 로그인한다.
- **정할 것**

  - 두 사람이 **같은 과정(프로젝트)을 나눠 작업**할지. 문항 DB는 PC 사이에 자동으로 합쳐지지 않는다. 한 과정은 한 PC에서 출제·검수하고, 옮길 때만 데이터 내보내기·가져오기를 쓴다.

- **정할 것**: 팀 서버 PC에 올려 여러 사람이 브라우저로 로그인해 쓸지, 쓴다면 시점.
