### 2. 프로토타입 구현 (약 4,100줄)
- **원고 등록**
  - PDF 변환: PPTX·DOCX는 Office COM으로 변환한다. HWP는 한컴 COM을 시도하고, 실패하면 PDF로 올리라고 안내한다.
  - 줄·bbox를 추출한다.
  - 인쇄 쪽수를 자동 감지한다. 샘플에서 PDF 1쪽 = 책 17쪽을 26/26 일치로 찾았다.
- **커버리지·슬롯 배분**
  - 페이지 글자 수에 비례해 배분하고, 페이지당 최소 1개·최대는 기대값의 2배로 둔다.
  - 생성 전에 난이도·유형·정답 위치·O/X·옳은/옳지 않은 비율을 슬롯으로 확정한다.
- **생성 파이프라인**: 페이지 단위로 생성하고, G1~G6 관문을 거친다. 탈락하면 재출제(최대 3회)하고, 그래도 실패하면 '수동 확인'으로 남긴다. 자동 중단 조건도 넣었다.

- **사람 검수(G7)**: 승인·수정·삭제·재검증 기능과 감사 로그
- **출력**

### 3. 검증
- pytest 21개가 모두 통과했다.
- 화면 5개를 AppTest로 실행해 예외가 없음을 확인했다.
- 실제 LLM(Claude Agent SDK, Sonnet 5.5)으로 2회 시험 출제했다.
  - 1차(8문항, $0.98): 난이도를 과대 표기하고, 참 보기를 원문 그대로 복사하는 문제가 보였다.
    → 프롬프트에 난이도별 출제 방법을 넣고, G5 실제 난이도가 두 단계 이상 차이 나면 탈락시키도록 고쳤다.
  - 2차(8문항, $0.74): 보기가 재진술로 바뀌었고, 통과 문항의 난이도 차이는 모두 한 단계 이내였다. '상' 단답형 1문항은 수동 확인으로 빠졌다(의도된 동작).
- 작업 중 버그 2건을 찾아 고쳤다.
  - 진위형 수치 환각 검사가 무력화되어 있었다.
  - PPTX를 PDF로 바꾸면 띄어쓰기가 사라졌다. LLM에는 슬라이드 원문을 주도록 바꿨다.
