# 평가문항 자동 출제 툴 (프로토타입)

원고(PDF·PPTX·DOCX·HWP)를 넣으면 출제자 대시보드에서 고른 옵션대로 성인 온라인 강의 평가문항(선다형·진위형·단답형)을 출제한다.
출력은 **양식 엑셀**과 **근거PDF**(원고 위에 출처를 하이라이트로 표시)다.

## 실행
### 휴대용 패키지(실무자 PC — Python 설치 불필요)
개발 PC에서 `python tools/build_portable.py`로 `dist/출제도구_휴대용_날짜.zip`(약 270MB)을 만든다. Windows 내장용 Python(이 PC와 같은 3.12.x)과 검증된 버전의 패키지(`requirements.lock.txt`)가 미리 들어 있다. 실무자는 **짧은 경로(예: `D:\출제도구`)에 풀고 `run.bat`**만 실행한다(처음 한 번 `Claude_로그인.bat`).
- 프로그램만 바뀌었을 때: `python tools/build_portable.py --app-only` → `출제도구_프로그램만_날짜.zip`을 설치 폴더에 덮어쓴다(python·projects·백업 폴더 유지).
- 패키지 버전을 올렸으면 `--lock`으로 고정본을 다시 만든 뒤 빌드한다. 패키지에는 **마지막 커밋 내용만** 들어간다(원고·projects 제외).

### 개발 PC
```
setup.bat              # 처음 한 번: Python 확인 → 가상환경 → 패키지 설치 → 설치 점검표
run.bat                # 대시보드 실행 http://localhost:8620 (이미 실행 중이면 브라우저만 연다)
Claude_로그인.bat       # 실제 출제용 Claude 구독 로그인(/login). Claude Code를 따로 설치할 필요 없음
Codex_로그인.bat        # (선택) Codex 설치 확인(Node.js 필요 시 안내 → npm 설치) → codex login → 로그인·모델 목록 확인
데이터_내보내기.bat     # 원고·출제 결과(projects)·설정을 ZIP 하나로 → 다른 PC로 이전
데이터_가져오기.bat     # ZIP을 이 파일 위로 끌어다 놓으면 가져온다(기존 데이터는 백업 폴더로)
```
- 경로가 길면(Windows 260자 제한) 패키지 설치가 실패한다. `D:\ExamGenerator`처럼 짧은 경로에 둔다.
- 설치 점검만 다시 하려면 `.venv\Scripts\python.exe -m exam_gen.tools.check_env`(휴대용은 `python\python.exe -m …`) (`--login`을 붙이면 Claude 호출로 로그인까지 확인).
- 문서: [사용 안내(담당자용)](docs/평가문항_자동출제_사용안내.html) · [노트북 설치 안내](docs/노트북_설치_안내.html) · 작업 기록 `docs/worklog/` · 할 일 `docs/TODO.md`

LLM은 사이드바 맨 아래 **AI 설정**에서 고른다. 생성, G4 독립 풀이, G5 검수마다 공급자를 다르게 지정할 수 있다.
예를 들어 생성은 Claude, G4·G5는 Codex로 두면 회사가 다른 모델이 정답을 교차 검증한다(시험 예정).
2026-10-22 같은 조건 비교에서 **출제는 Claude가 낫다**(Codex보다 2배 빠르고 함정이 정교함). 담당자 협의(2026-10-23)로 당분간 **Claude 구독**으로 출제하며, 새로 설치해도 기본 공급자는 Claude 구독 로그인이다.

| 공급자 | 인증 | 비고 |
|---|---|---|
| 데모(mock) | 없음 | LLM 없이 모의 문항을 만든다. 화면 흐름 확인용이며 납품에 쓰지 않는다 |
| Claude 구독 로그인 | OAuth: `Claude_로그인.bat` → `/login` | Claude Agent SDK(내장 claude.exe 사용). 구독 사용량에서 차감 |
| Codex 구독 로그인 | OAuth: `Codex_로그인.bat`(또는 터미널 `codex login`, ChatGPT 계정) | `codex exec --output-schema`. 구독 사용량만 쓴다. Codex는 패키지에 들어 있지 않아 Node.js + `npm install -g @openai/codex`가 필요 |
| Anthropic API | API 키 | 키는 Windows 자격 증명 저장소에 보관된다 |
| 사내 LiteLLM | 주소 + API 키 | OpenAI 호환. 키는 자격 증명 저장소에 보관된다. **실제 서버로는 아직 시험 전**. 딥시크 등 OpenAI 호환 API도 이 경로로 연결(공식 딥시크 API는 원고가 해외로 전송되므로 보안 정책 확인 필요) |

**모델 선택**: 역할별(생성·G4·G5)로 목록에서 고른다. Claude는 Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / 계정 기본값, Codex는 이 PC의 Codex가 받아 둔 모델 목록(`~/.codex/models_cache.json`), 목록에 없으면 '직접 입력'. 새 설치 기본값은 **Opus 5.5** — 지금까지 시험 출제와 시간 실측은 모두 Opus 5.5(계정 기본값)로 했다(2026-10-27 확인). 실제로 응답한 모델은 문항과 배치 기록에 남고 프로젝트 관리 → 출제 이력 '실제 모델'에 보인다.
- **출제는 Opus 권장**(2026-10-27 같은 32슬롯 비교): Sonnet 출제는 더 빠르지 않았고(13.7~16.7분 vs 12분) 재시도가 3~4배였다. Codex 블라인드 교차 검수에서 문제없음 비율이 Opus 87.5%(28/32), Sonnet 출제 68.8%(22/32).

'연결·로그인 확인' 버튼으로 각 공급자의 로그인 상태를 확인한다. 구독 로그인 토큰은 각 CLI가 관리하며, 이 툴은 저장하지 않는다.

## 흐름
화면은 처음 쓰는 실무자 기준으로 정리했다(2026-10-28 UX 개편). 사이드바 맨 위에서 **프로젝트**를 고르고(목록은 '구분 메모 — 과정명'으로 최근 만든 순, 펼치면 전체 제목이 보인다), 아래 **진행 순서 1~6**(원고 등록 → 기출문제 등록(선택) → 출제 옵션 → 출제 진행 → 검수 → 출력)을 따라간다. 끝낸 단계에는 ✓, 다음에 할 단계에는 '◀ 지금 할 일'이 붙는다. 품질 리포트·이의신청 조회·프로젝트 관리는 **관리** 묶음에 있다. 각 화면 끝에 '다음 단계' 버튼이 있고, 용어는 화면에 바로 풀어 쓴다(배치 → 회차, LLM 재검증 → AI 재검증 등). 업로드 칸 안내도 한글이다.

0. **프로젝트 관리**: 새 프로젝트는 **과정명 + 구분 메모**로 만든다(화면 이름 '과정명 · 메모', 같은 이름 금지). 출제 프롬프트에는 과정명만 전달하고 구분 메모는 화면 구분용이다. 목록에서 만든 날·마지막 수정·원고·문항 상태·출제 이력(배치별 AI·호출 수·시간)·사용 모델(프롬프트 버전)을 보고, 이름 바꾸기(영향 안내·확인 체크, 예전 이름 기록)·**삭제(휴지통 `projects/_삭제됨`)·되살리기·휴지통 비우기**를 한다.
1. **원고 등록**(① 업로드 → ② 쪽수 확정 → ③ 차시·출제 제외 → ④ 과정 정보): 같은 파일 이름은 중복 등록을 막고 새 판 교체로 안내한다. 쪽수는 [이 쪽수로 확정]을 눌러야 출제할 수 있다. ③은 **범위로 한꺼번에 지정**(쪽 범위마다 차시 지정·출제 제외·제외 풀기, 누르면 바로 저장)하고, 한두 쪽만 표에서 고친다.
1-0. **원고 새 판으로 교체**(원고 등록 화면): 수정본을 올리면 원고 ID·문항 번호를 유지한 채 쪽 짝짓기(본문 유사도)와 근거 문장 재검색으로 **쪽수·근거 위치를 자동으로 맞춘다(AI 사용 없음)**. 근거 문장이 바뀌거나 사라진 문항만 '원고 변경'(내용 변경·내용 삭제)으로 표시하고 변경 보고서를 남긴다. 비교 기준은 **바로 전 판**이라 이미 고친 문항은 다시 표시되지 않는다. 원고가 확정되면 **[변경 문항 일괄 처리]**(예상 호출 수 표시 후 실행)로 AI가 바뀐 부분만 고치거나(내용 변경) 같은 조건으로 재출제한다(내용 삭제). 문항 번호는 유지되고 고친 칸은 엑셀 검수용 시트에 노란색으로 표시된다. 검수 화면 '원고 변경' 대기열에서 문항별 처리도 가능. 이전 판은 `pdf/{원고ID}_v{n}.pdf`, `runs/manuscript/`에 보관.
1-1. **기출문제 등록**: 이미 출제·서비스한 문항을 올리면 추가 출제에서 겹치지 않게 제외한다. 제출 양식 엑셀은 바로 읽고(토큰 0), 그 밖의 엑셀·CSV·한글·워드·PDF는 AI가 표준 양식으로 통일한다(예상 호출 수 표시). 저장 전 미리보기에서 확인·수정. 기출은 상태 `prior`로 저장되어 출력·검수·통계에서 빠지고, G6 중복 검사와 같은 쪽 회피 목록에만 쓰인다. **원고를 먼저 등록한다** — 기출은 원고의 가장 관련 있는 쪽에 연결되어야 회피 목록에 들어간다. 원고보다 먼저 올린 기출은 원고를 등록할 때 자동으로 연결되고, 원고를 바꾼 뒤에는 **[기출 쪽 다시 연결]**(AI 없음)로 다시 계산한다.
2. **출제 옵션**: 출제 종류(최초 출제/추가 출제/페이지 재출제), 문항 수(기본 300 + 여유 5%), 난이도 % 4칸(최상·상·중·하), 유형 %, 페이지별 문항 수 직접 지정. 아래 **출제 전 점검**(쪽수 확정·차시·학습목표·사용할 AI·예상 시간)을 보고 확인 체크 후 [출제 시작]. 예상 시간은 이 PC의 출제 기록 실측으로, 기록이 없으면 개발 시험 실측(Opus 5.5 문항당 약 23초)으로 계산한다.
   - 추가 출제는 난이도별 수량 또는 총 수량 + %로 입력한다.
   - **빠른 출제**(세부 옵션): 급할 때 AI 독립 풀이·검수(G4·G5)를 생략하고 무료 검사(형식·근거 대조·규칙·중복)만 한다. 시간·사용량 약 1/3(추정). 문항은 'AI 검증 생략'으로 표시되고 승인 전에 품질 리포트의 **[생략한 AI 검증 실행]**(여러 문항을 묶어 검증 — 호출 적음)이 필요하다.
3. **출제 진행**: 진행률, 관문별 탈락, 페이지 커버리지(0문항·과밀 경고), 중지·재개
4. **품질 리포트**: 항목별 A~D 등급, 목표 대비 난이도 부족분, 같은 원리 반복 묶음(묶음마다 하나만 남기기), 시의성 확인 목록
5. **검수**: 문항과 원고 하이라이트를 나란히 보고 수정·승인·삭제한다. **승인한 문항만 최종 출력에 들어간다.**
6. **출력**: 양식 엑셀(최종 시트, 숨김 검수용 시트, 검증리포트), 근거PDF(문항별 추출본, 원고 전체 표시본)
   - **출력 대상**: 전체(검수 없이, 자동 검증 탈락 문항 포함 — 엑셀 연한 빨강 행) / 자동 검증 통과 / 승인한 문항만(납품 확정용)
   - **최종 문항 자동 선정**: 여유분까지 출제한 문항에서 목표 수만큼 목표 분포(난이도·유형·차시)에 맞춰 고른다. 같은 원리 묶음은 1문항, 정답 단서·이의 제기·AI 검증 생략 문항은 뒤로(토큰 0). 출력 대상 '최종 선정 문항만', 검수 화면에서 선정 여부 변경.
   - **시험지 PDF**(검토·회의용): 정답·해설 포함/제외, 차시별 구분.
   - 단답형 정답 칸은 `정답 (유사답변: …)` 형태. 근거 하이라이트는 정답 근거 **노랑**, 함정 원문 **파랑**
   - **출력 이력**: 출력할 때마다 문항번호 ↔ 문항키 ↔ 그때의 문항 내용(해시·스냅숏)을 `runs/exports.jsonl`에 남기고, 예전 출력물을 다시 받을 수 있다.
- **난이도 기준**(관리 메뉴): 하·중·상·최상의 정의를 담당자 지침대로 넣고 '확정'한다. 출제·AI 검수 프롬프트가 이 기준을 쓴다(`exam_gen/difficulty_policy.py`, `data/difficulty_policy.json`). 받은 기준 문서에는 비율만 있어, 기본값은 블룸 인지 수준에 맞춘 **임시 기준안**이다(하=기억, 중=이해, 상=적용, 최상=분석·종합/자격시험형). 출제 전 점검표와 엑셀 검증리포트에 기준 상태(임시/확정)가 표시되고, 문항마다 출제 당시 기준 버전이 남는다.
- **담당자 판정 난이도**(검수 화면): 문항의 난이도를 사람이 직접 정한다. AI 판정보다 우선하고(엑셀·최종 선정에 반영, 승인 유지), 쌓이면 난이도 보정 출제의 판정 비율표가 담당자 판정으로 계산된다.
7. **이의신청 조회**: 서비스된 문항을 **모든 프로젝트에서** 찾는다(문제 문장 일부 붙여넣기 — 띄어쓰기·문장부호 무시, 출력 뒤 고친 문항은 출력 당시 내용으로도 / 문항키 / 출력 파일 + 문항번호). 한 화면에서 문항·출력 당시 내용과의 차이·원고 근거 하이라이트·G4 독립 풀이·G5 함정 판정·출력 이력을 보고, 처리 결과(정답 인정·복수 정답·수정·폐기·기각)를 기록한다(`runs/appeals.jsonl`, 폐기는 삭제 처리). 보고·회신용 **이의신청 검토서 PDF**를 만든다. 토큰 0. 서비스 시스템에 문항키(엑셀 숨김 R열)를 함께 보관하면 가장 빠르다.

출제가 끝나거나 멈추면 **윈도우 알림**을 띄우고, 출제 진행 화면에 예상 남은 시간을 보여 준다. AI 사용 한도·과부하 오류는 1~2분 기다렸다가 다시 시도한다. 출제 끝·원고 교체 전·삭제 전에 **자동 백업**(`백업/<프로젝트>/`, 최근 10개, 프로젝트 관리 화면에서 되돌리기).

대시보드는 마지막에 작업한 프로젝트를 기억한다(`data/ui_state.json`, 새로고침·재시작 후에도 유지).

CLI: `python -m exam_gen.cli new|run|export|report|pool` (exam_gen/cli.py 참고, `run --provider claude_agent_sdk|codex_cli`)

## 신뢰도 장치 — 문항 하나가 통과해야 하는 관문

| G3 규칙 | 문어체, 단답 조사 힌트(받침에 따라 모양이 바뀌는 조사만 — '에·의·도·만'은 힌트 아님), 조합형 '모두', 진위형 O 해설 반복, 표현 정확도(의무·금지·가능·권고), 절대어, '원고'·쪽수 노출, 지시어, **단답형 정답어 노출**, 괄호 둘 이상이면 '공통으로', 허용 답안 중복 정리, **시의성 경고**(기관명·법령·금액·전화번호·날짜), 선다형 질문형 발문(사례형의 '…것은?' 뒤 줄바꿈·같은 줄 [사례] 블록·'(단, …)' 단서 괄호 인정), **거짓 보기의 상식 단서 표현**('확인 생략', '~만 하면 된다' 등 — AI 검증 전에 걸러 다시 출제) | validate/rules.py, validate/freshness.py |

| G6 중복 | 기존 전체 문항과 어절 자카드·판단 포인트·근거 위치 비교 | validate/dedup.py |
| 최종 풀 점검 | 배치가 끝나면 통과 문항 전체에서 같은 판단 원리를 반복해 묻는 묶음을 표시(탈락 아님) | validate/pool_review.py |

- 탈락한 슬롯은 사유를 붙여 다시 출제한다(기본 3회). 그래도 실패하면 '수동 확인'으로 남기며 자동으로 출력되지 않는다.

## 원고 전반 출제
- `plan/coverage.py`가 **차시별 문항 수를 분량(글자 수)에 비례해 먼저** 정하고, 차시 안에서 페이지에 나눈다.
  - 문항이 페이지보다 적으면 페이지 순서를 따라 분량 간격으로 고르게 뽑는다(한 구간에 몰리지 않게).
  - 문항이 페이지보다 많으면 페이지마다 최소 1문항, 최대는 기대값의 2배다.
  - 글자 수가 적은 페이지(그림·빈 쪽)는 자동으로 출제 제외된다.
- 난이도 '최상'은 **자격증 시험의 실무 사례형**(담당자 협의 2026-10-23): 짧은 사례(상황·조건·수치)에 원고의 개념·절차 2개 이상을 적용해야 풀리고, 보기는 모두 그럴듯한 실무 대응. 관련 페이지를 인접 차시까지 넓게 준다. 사례 없는 진술 판별은 '상'까지로 판정한다.
- `plan/slots.py`가 생성 전에 유형·난이도·정답 위치(①~④ 각 25%)·O/X(5:5)·옳은/옳지 않은(20:80)을 슬롯으로 확정한다. 유형별 허용 난이도: 단답형 하·중, 진위형 상까지(진위형 '상'은 정답 X라 진위형의 절반까지).
- **난이도 보정 출제**(`plan/calibrate.py`, 출제 옵션 세부 옵션, 기본 켬): AI 검수(G5)는 출제 의도보다 한 단계 낮게 판정하는 경향이 있다(2026-10-27~28 실측 182문항: 상 슬롯 94%가 중, 최상 사례형 93%가 상, 중 42%가 하). 이 판정 비율표(`criteria.yaml` `difficulty_calibration`, 이 PC 출제 기록과 섞어 씀)로 **판정 기준 목표 비율에 가깝도록** 슬롯 난이도를 정하고, 최종 자동 선정이 판정 난이도로 비율을 맞춘다. 300문항 예: 출제 지시 최상 53·상 140·중 96·하 26 → 예상 판정 최상 4·상 58·중 190·하 64. **최상은 목표에 못 미친다**(최상 기준 담당자 협의 중). 상·최상 슬롯은 문항당 약 1분이라 예상 시간에 더한다.
- 생성은 페이지 단위로 한다. 같은 페이지의 기존 문항은 회피 목록으로 넘긴다.
- AI는 문항을 쓰기 전에 **설계(design)**를 먼저 적는다: 거짓 보기를 원고의 어느 조건·대상·순서를 바꿔 만들지와 보기 4개의 공통 어조(정답 단서 방지), 상·최상은 정답 판단에 필요한 두 곳(PROMPT_VERSION 2026-10-28.3). 소량 시험에서 첫 시도 정답 단서 비율 31% → 13%.
- 추가 출제는 기존 문항이 기대보다 적은 페이지에 더 배분한다.

## 담당자와 정할 것
- LLM 경로(API 키 / 사내 LiteLLM / 구독)와 모델, 원고를 어떤 외부 AI 서비스까지 보내도 되는지(딥시크 포함)
- 유형별 기본 비율(현재 선다 50 / 진위 30 / 단답 20), 난이도 기본값(최상 5 / 상 15 / 중 60 / 하 20). 선다형 옳지 않은 것 : 옳은 것 = 8 : 2(조합형은 옳은 것에 포함)
- 문항번호 방식(양식 연번 / 유형별), NCS 열(N~P) 채움 여부
- 장 단위 원고에서 차시를 나누는 기준
- 현실적인 난이도 목표와 **최상 기준**: AI 검수가 출제 의도보다 한 단계 낮게 판정한다(2026-10-28 실측: 상 슬롯 약 90%가 중, 최상 사례형 약 90%가 상, 진짜 최상 9개 중 1개). 자격시험형 사례 문항을 최상으로 볼지 담당자 확인 필요
- 실제 원고의 차시 기준(절 5개 / 소절 21개), 부록 출제 여부, 공식 학습목표
- 태도·원칙 중심 과정에서 상식으로 풀리는 기초 문항을 어디까지 허용할지
- 원고와 현재 사실(기관명·법령)이 다를 때 기준. 웹 검색 기반 사실 검증(지침 [8]-6)은 아직 구현하지 않았고, 지금은 시의성 경고만 붙인다.
