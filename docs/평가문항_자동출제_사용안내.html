평가문항 자동 출제 사용 안내

강의 원고를 올리면 원고 전체에 고르게 평가문항을 만들고, 자동 검증과 사람 검수를 거쳐 제출 양식 엑셀과 원고 위에 출처를 표시한 근거PDF로 내보내는 도구입니다. 이 문서는 처리 과정(파이프라인)과 화면별 사용법을 한 장에 정리했습니다.

1핵심 원칙 세 가지

★ 원고 전반 출제

출제 전에 차시별 문항 수를 분량에 비례해 먼저 정하고, 차시 안에서는 페이지 순서대로 고르게 나눕니다. 특정 부분에 몰리지 않고, 필요하면 페이지별 문항 수를 직접 지정할 수 있습니다.

★ 원고 위 출처 표시

AI가 근거 문장을 인용하면 프로그램이 원고에서 그 문장을 직접 찾아 줄 단위로 색칠하고 문항 라벨을 붙입니다. 원고에서 찾지 못한 문항은 출력되지 않습니다.

★ 신뢰도

문항마다 여섯 단계 자동 검증(틀린 보기가 원고와 실제로 모순되는지까지)을 거칩니다. 납품용 출력은 사람이 승인한 문항만 들어가고, 검수 전에 전체를 미리 뽑아 볼 때는 탈락 문항이 표시됩니다. 승인 후 내용을 고치면 승인이 풀리고 다시 검증해야 합니다.

3문항 하나가 거치는 검증 단계

화면과 리포트에서는 각 단계를 G1~G7로 부릅니다.

G1
형식 검사
보기 4개, 정답 번호, 유형별 형식이 맞는지
G2
근거 대조
인용한 근거 문장을 원고에서 실제로 찾음. 쪽수는 프로그램이 확정
G3
지침 규칙
문어체, '원고'·쪽수 노출, 단답 조사 힌트, 절대어, 발문 형식 등
G4
독립 풀이
정답을 모르는 별도 AI가 문항을 풀어 정답이 일치하는지
G5
AI 검수
정답·해설·보기·이의 제기·지엽성 등 9개 항목, 함정 판정(틀린 보기가 원고와 실제로 모순되는지), 단답형 용어 판정, 실제 난이도
G6
중복 검사
기존 문항과 문장·판단 포인트·근거 위치가 겹치는지
G7
사람 승인
검수 화면에서 승인한 문항만 최종 출력
탈락하면탈락 사유를 알려 주고 같은 조건으로 다시 출제합니다(기본 3회). 그래도 통과하지 못하면 수동확인으로 분류되고 출력되지 않습니다.

신뢰도를 위한 추가 장치

  • 함정 판정: 틀린 보기마다 '원고와 모순 / 원고와 동시에 성립 가능 / 원고에 없을 뿐 / 조건 부족'을 따로 판정합니다. 모순이 아니면 탈락합니다. 근거 문장이 원고와 일치해도 그 보기가 틀렸다는 증명은 아니기 때문입니다.
  • 정답 단서 막기: AI가 문항을 쓰기 전에 '거짓 보기를 원고의 무엇을 바꿔 만들지, 보기 4개의 공통 어조'를 먼저 설계합니다. 거짓 보기에 '확인은 생략해도 된다', '~만 하면 된다'처럼 상식으로 걸러지는 표현이 있으면 프로그램이 먼저 걸러 다시 출제하고, 그래도 원고를 몰라도 정답이 보이면 AI 검수가 한 번 다시 출제시킵니다(시험 결과 첫 시도 정답 단서 31% → 13%).
  • 단답형 점검: 정답어가 지문에 그대로 나오거나, 원고가 정의한 용어가 아닌 일반 표현이면 탈락합니다. 정답과 띄어쓰기·조사만 다른 허용 답안은 자동으로 정리합니다.
  • 시의성 표시: 기관명·법령·금액 기준·전화번호·날짜가 든 문항에 '시의성 확인' 경고를 붙입니다. 정답이 그 정보에 달려 있으면 '정답 관련'으로 따로 표시합니다(외부 확인은 하지 않음).
  • 같은 원리 반복 점검: 문장은 달라도 같은 원리를 묻는 문항 묶음을 찾아 표시합니다. 검수자가 묶음마다 하나만 남길 수 있습니다.

근거 대조 결과 표시

  • L2 (원문 일치): 근거 문장이 원고와 글자 단위로 일치합니다.
  • L1 (부분 일치): 일부만 일치합니다. 승인하려면 검수자가 원고 하이라이트를 직접 보고 '근거 확인'에 체크해야 합니다. 숫자·부정어·의무/금지 표현이 바뀐 경우는 L1로도 인정하지 않습니다.

4화면별 사용법

왼쪽 사이드바는 위에서부터 프로젝트(작업할 과정 고르기·새 프로젝트) → 진행 순서(홈, 1 원고 등록 ~ 6 출력) → 관리(품질 리포트·이의신청 조회·프로젝트 관리) → AI 설정입니다. 끝낸 단계에는 초록 ✓, 다음에 할 단계에는 주황 ◀ 지금 할 일이 붙으므로 표시를 따라가면 됩니다. 각 화면 아래의 '다음' 버튼으로도 넘어갈 수 있습니다. 마지막에 작업한 프로젝트는 다시 열어도 그대로 선택되어 있습니다.

홈진행 순서
  1. '지금 할 일'에 현재 상태에 맞는 다음 단계와 바로 가기 버튼이 나옵니다. 프로젝트가 없으면 사이드바의 '새 프로젝트'부터 안내합니다.
  2. 진행 단계 1~6의 상태(완료·진행 중·대기·선택)와 문항 수를 확인합니다. 처음이면 '사용 안내'를 펼쳐 용어 풀이를 봅니다.
프로젝트 관리관리
  1. 새 프로젝트는 사이드바에서 과정명(필수)과 구분 메모(예: 2026 상반기 · 300문항 본출제)를 입력해 만듭니다. 같은 이름은 만들 수 없습니다.
  2. 목록에서 만든 날, 마지막 수정, 원고, 문항 수, 출제 횟수, 사용한 AI·모델을 확인합니다.
  3. 표에서 행의 맨 왼쪽 칸을 눌러 고르면 출제 이력(회차별), 사용 모델, 이름 바꾸기, 백업·되돌리기, 삭제가 나옵니다. 이름은 출제 프롬프트·출력 파일 제목에 쓰이므로 바꿀 이름을 확인하고 체크한 뒤 저장합니다. 삭제한 프로젝트는 휴지통에서 되살릴 수 있습니다.
1 원고 등록진행 순서

화면 안에서 ①~④ 순서대로 진행하며, 단계마다 '완료/할 일' 표시가 붙습니다.

  1. ① 원고 파일 올리기: 파일을 고르고 '파일 등록'을 누릅니다. HWP는 한글 프로그램으로 PDF 변환을 시도하고, 안 되면 한글에서 PDF로 저장해 올립니다. 같은 이름의 파일은 다시 등록되지 않습니다(수정본은 아래 '새 판으로 교체').
  2. ② 쪽수 확정: 원고에 인쇄된 쪽 번호를 자동으로 찾습니다. 오른쪽의 머리말·꼬리말 그림과 비교해 맞으면 '이 쪽수로 확정'을 누릅니다. 확정하기 전에는 출제를 시작할 수 없습니다.
  3. ③ 차시 나누기·출제 제외: '범위로 한꺼번에 지정'에서 순번 범위를 정해 차시를 지정하고, 표지·목차·부록처럼 출제하지 않을 범위는 '출제 제외'를 고릅니다(누르면 바로 저장). 한두 쪽만 고칠 때는 아래 표에서 바꾸고 '페이지 설정 저장'을 누릅니다. 차시마다 분량에 맞춰 문항 수를 먼저 나누므로 차시를 바르게 지정해야 원고 전체에 고르게 출제됩니다.
  4. ④ 과정 정보: 과목/주제명과 학습목표를 입력합니다. 학습목표는 AI가 '중요한 내용인지' 판단하는 기준입니다.
  5. 원고가 수정되면 화면 맨 아래 '원고 수정본이 왔을 때 — 새 판으로 교체'를 펼쳐 새 파일을 올립니다. 바로 전 판과 비교해 쪽이 밀린 문항은 쪽수를 자동으로 고치고, 근거 문장이 바뀐 문항·사라진 문항만 '원고 변경'으로 표시합니다(AI 사용 없음, 이전 판은 보관).
  6. 원고가 확정되면 '변경 문항 일괄 처리'를 누릅니다. 예상 AI 호출 수를 먼저 보여 주고, 바뀐 문항은 바뀐 부분만 고치고 사라진 문항은 같은 조건으로 다시 출제합니다. 고친 칸은 엑셀 검수용 시트에 노란색으로 표시됩니다. 이미 고친 문항은 다음 판에서 다시 표시되지 않습니다.
2 기출문제 등록선택
  1. 원고를 먼저 등록한 뒤 진행합니다. 기출이 없으면 건너뜁니다. 이미 시험에 쓴 문항을 올리면 추가 출제 때 같은 내용을 피합니다.
  2. 제출 양식 엑셀은 바로 읽습니다(AI 사용 없음). 다른 형식의 엑셀·CSV·한글·워드·PDF는 AI가 표준 문항 형식으로 바꿉니다(예상 호출 수 먼저 표시).
  3. 미리보기 표에서 확인·수정한 뒤 저장합니다. 기출문제는 검수·출력·통계에 들어가지 않습니다.
3 출제 옵션진행 순서
  1. 출제 종류를 고릅니다: 최초 출제 / 추가 출제(기존과 겹치지 않게) / 페이지 재출제(지정한 페이지만).
  2. 난이도 비율(최상·상·중·하, 합계 100)과 유형 비율(선다·진위·단답, 합계 100)을 정합니다.
  3. 문항 수와 여유분(삭제에 대비해 조금 더 출제)을 정하면 페이지별 배분, 예상 시간, 구성 요약이 바로 나옵니다.
  4. 아래 출제 전 점검에서 쪽수 확정·차시·학습목표·사용할 AI·예상 시간을 확인합니다. 문제가 있으면 이유가 표시됩니다. 예상 시간을 확인했다는 체크를 한 뒤 '출제 시작'을 누릅니다('옵션만 저장'은 출제하지 않고 설정만 남김).
  5. 난이도 보정 출제(세부 옵션, 기본 켬): AI 검수는 출제 의도보다 난이도를 한 단계 낮게 판정하는 경향이 있습니다(실측: '상'으로 낸 문항의 약 90%가 '중'). 켜 두면 그만큼 어려운 문항을 더 출제하도록 지시해 검수 판정 기준으로 목표 비율에 가깝게 맞춥니다. 화면에 '출제 지시 난이도'와 '예상 판정'이 함께 나옵니다. 상·최상 문항은 오래 걸려 예상 시간이 늘어납니다. 최상은 아직 목표에 못 미칩니다(9절 결정 사항).
  6. 선다형은 '옳지 않은 것' : '옳은 것' = 8 : 2가 기본입니다(요약 카드에 실제 비율 표시). 최상 난이도는 자격시험처럼 짧은 실무 사례를 주고 원고 개념 2개 이상을 적용해 판단하게 합니다.
  7. 빠른 출제(급할 때만): AI 독립 풀이·AI 검수를 생략해 시간이 약 1/3로 줄어듭니다. 형식·근거 대조·규칙·중복 검사는 그대로 합니다. 생략한 검증은 나중에 품질 리포트의 '생략한 AI 검증 실행'으로 한꺼번에 할 수 있습니다.
4 출제 진행진행 순서
  1. 진행률, 통과·경고·수동확인 수, 검증 단계별 탈락 수, 페이지별 분포가 실시간으로 바뀝니다.
  2. 중간에 멈추거나 인터넷이 끊겨도 '이어서 출제'로 남은 부분만 계속할 수 있습니다.
  3. 예상 남은 시간이 표시되고, 끝나거나 멈추면 윈도우 알림이 뜹니다. AI 사용 한도·과부하 오류는 1~2분 기다렸다가 다시 시도합니다.
  4. 이 화면을 닫아도 출제는 계속됩니다(대시보드 실행 창은 닫지 않음). 끝나면 '다음: 품질 리포트' 또는 '검수로 바로 가기'로 넘어갑니다. 출제가 끝날 때마다 프로젝트가 자동으로 백업됩니다.
품질 리포트관리
  1. 정답·이의 제기·출처·원고 전반·형식·변별력·난이도를 A~D 등급으로 보여 줍니다(A 납품 수준, D 재출제 권장).
  2. 목표 대비 실제 난이도·유형·정답 위치 분포를 확인합니다.
  3. 문제 문항 목록에서 하나를 고르면 검수 화면에서 바로 열립니다.
  4. 목표보다 모자란 난이도가 있으면 따로 경고합니다(낮게 재분류된 문항은 목표를 채운 것이 아님).
  5. 같은 원리 반복 점검: 묶음마다 '남길 문항'을 고르고 '나머지 삭제'를 누르면 정리됩니다. 문항을 고친 뒤 '다시 점검'할 수 있습니다.
  6. '보기 다듬기·시의성 확인·원리 반복'은 참고 항목으로, 등급에는 넣지 않습니다.

등급은 AI 검수 경고를 센 값입니다. 실제 응시 결과가 아니며, 무엇을 먼저 볼지 정하는 데 씁니다.

5 검수진행 순서
  1. 위쪽 대기열에서 확인 필요(경고·수동확인)부터 봅니다. 왼쪽 목록에서 문항을 고르면 오른쪽에 문항, 원고 근거(하이라이트), 검증 상세, 이력이 나옵니다.
  2. 담당자 판정 난이도(하·중·상·최상)를 누르면 이 문항의 난이도를 직접 정합니다. AI 판정보다 우선하며, 다시 누르면 지워집니다. 문항 내용은 바뀌지 않아 승인은 유지됩니다.
  3. 화면 맨 위 오른쪽에 검수자 이름을 한 번 넣으면 다음에도 기억합니다. 승인을 누르면 다음 문항으로 넘어갑니다. 경고 내용은 승인 전에 반드시 읽습니다. 문항이 많아도 목록은 정해진 높이 안에서만 스크롤되고, 대기열·상세 필터(유형·난이도·차시·쪽수·검색)로 좁혀 볼 수 있습니다.
  4. 고칠 내용이 있으면 '문항 수정'에서 고친 뒤 AI 재검증을 눌러야 승인할 수 있습니다.
  5. 쓸 수 없는 문항은 삭제합니다(사유 기록). 일괄 승인은 경고가 없는 '자동통과' 문항에만 적용됩니다.
  6. 대기열 '원고 변경': 원고 새 판에서 근거가 바뀐 문항입니다. 바뀐 원고 문장을 보고 직접 고치기·그 문항만 AI 수정·삭제·그대로 두기 중에서 고릅니다. 대기열 'AI 검증 생략': 빠른 출제로 만든 문항입니다.
  7. 최종 선정을 했다면 문항마다 '최종 선정에 포함'을 켜고 끌 수 있습니다.
6 출력진행 순서
  1. 출력 대상을 고릅니다. 전체(검수 없이): 삭제한 문항만 빼고 모두 — 자동 검증 탈락 문항은 엑셀에 연한 빨강 행으로 표시 / 자동 검증 통과 / 승인한 문항만(납품 확정용) / 최종 선정 문항만.
  2. 최종 문항 자동 선정: 여유분까지 출제한 문항에서 목표 수만큼 난이도·유형·차시 목표에 맞춰 고릅니다. 같은 원리 묶음은 1문항만, 정답 단서·이의 제기·검증 생략 문항은 뒤로 미룹니다(AI 사용 없음). 모자란 난이도는 따로 알려 줍니다.
  3. 출력 범위(전체 또는 특정 회차)를 고릅니다. 회차는 '출제 시작'을 한 번 누른 단위입니다(처음 출제 = 1회차, 추가 출제마다 2, 3 …).
  4. 엑셀, 문항별 근거PDF, 원고 전체 근거PDF, 시험지 PDF(검토·회의용, 정답·해설 포함 여부 선택)를 만들고 내려받습니다. 파일은 프로젝트 폴더의 exports에도 저장됩니다.
  5. 출력 이력: 언제 어떤 파일을 몇 문항으로 만들었는지, 그때 각 번호가 어떤 문항이었는지 기록되고 예전 파일을 다시 받을 수 있습니다.
난이도 기준관리
  1. 하·중·상·최상을 무엇으로 나눌지 정합니다. 여기서 정한 기준으로 AI가 문항을 출제하고 난이도를 판정합니다.
  2. 처음에는 교육 평가에서 널리 쓰는 블룸 인지 수준에 맞춘 임시 기준안이 들어 있습니다(하=기억, 중=이해, 상=적용, 최상=분석·종합/자격시험형 사례). 담당자 지침이 있으면 그 내용을 넣고, 없으면 기준안을 보고 고칠 곳만 고친 뒤 '담당자가 확인한 기준입니다(확정)'에 체크해 저장합니다.
  3. 기준을 바꾸면 이후 출제·AI 재검증부터 적용됩니다. 바꾼 기록이 남고, 문항마다 출제 당시 기준이 기록됩니다.
  4. 검수 화면의 담당자 판정 난이도로 문항마다 난이도를 직접 정할 수 있습니다. 담당자 판정은 AI 판정보다 우선하고, 쌓이면 '난이도 보정 출제'가 담당자 기준에 맞춰집니다.
이의신청 조회관리
  1. 이의신청서의 문제 문장 일부를 붙여넣거나, 문항키(예: K00012) 또는 출력 파일 + 문항번호로 찾습니다. 모든 프로젝트를 한꺼번에 찾습니다.
  2. 한 화면에서 문항, 원고 근거 하이라이트, AI 독립 풀이·함정 판정 근거, 출력 이력을 봅니다. 출력한 뒤 문항을 고쳤다면 출력 당시 내용도 함께 보입니다.
  3. 처리 결과(정답 인정·복수 정답·문항 수정·문항 폐기·기각)와 메모·처리자를 기록하고, 보고·회신용 이의신청 검토서 PDF를 만듭니다.

8자주 묻는 질문

승인했는데 출력에 안 나옵니다.

출력 대상('승인한 문항만'·'최종 선정 문항만')과 출력 범위(회차)를 확인합니다. 승인 후 내용을 고치면 승인이 풀리므로 'AI 재검증' 후 다시 승인해야 합니다.

경고가 붙은 문항은 쓰면 안 되나요?

아닙니다. 경고는 '사람이 한 번 보라'는 뜻입니다. 경고 내용을 읽고 문제없다고 판단하면 승인합니다. AI 검수가 정답·이의 제기·보기에 대해 '그대로 쓰면 안 됨'으로 판정한 문항은 자동으로 탈락(재출제)되고, 경고 문항에는 '확인 권장' 수준의 지적만 남습니다.

문항 키(K00001)가 다른 과정과 겹칩니다.

문항 키는 과정(프로젝트)마다 1번부터 매깁니다. 사이드바에서 선택한 프로젝트 이름을 확인합니다.

HWP 원고가 변환되지 않습니다.

한글 2010 이상은 자동 변환이 됩니다(처음 한 번 보안 승인 모듈 등록 필요). 한글 2007은 PDF 저장 기능이 없어, 한글에서 '인쇄 → Haansoft PDF'로 저장한 파일을 올립니다.

원고와 문항은 어디에 저장되나요?

모두 이 PC의 프로그램 폴더 안(projects/)에만 저장됩니다. 원고 파일은 저장소(GitHub)에 올리지 않습니다. AI 출제 시에는 해당 페이지 원문이 AI 서비스로 전송됩니다.

비슷한 내용을 묻는 문항이 여러 개 나왔습니다.

원고가 강조하는 핵심 원리(예: '상대와 분리된 경로로 확인')는 여러 쪽에 나와 문항도 반복되기 쉽습니다. 출제가 끝나면 자동으로 '같은 원리 반복' 묶음을 표시하므로, 품질 리포트에서 묶음마다 하나만 남기거나 묻는 조건이 다르면 그대로 둡니다.

원고의 기관명·법령이 바뀌었으면 어떻게 되나요?

자동 검증은 원고를 기준으로 하므로 원고에 적힌 옛 명칭은 그대로 통과합니다. 대신 기관명·법령·금액 기준·전화번호·날짜가 든 문항에는 '시의성 확인' 경고가 붙고, 품질 리포트에 목록으로 나옵니다. 특히 '정답 관련'으로 표시된 문항은 원고 집필자·담당자와 최신 여부를 확인하세요.

AI가 만든 문항을 그대로 써도 되나요?

자동 검증은 사람 검수를 대신하지 않습니다. 실제 원고 시험 출제에서 정답 오류는 0건이었지만, 상식으로 정답이 보이는 보기와 단답형의 다른 표현 문제가 남아 있어 사람 검수가 꼭 필요합니다.

문항 난이도가 설정한 비율보다 낮게 나옵니다.

AI 검수는 '정답을 고르는 데 꼭 필요한 최소 지식'으로 난이도를 판정해, 출제 의도보다 한 단계 낮게 보는 경향이 있습니다(실측: 상 → 중 약 90%, 최상 사례형 → 상 약 90%). 출제 옵션의 난이도 보정 출제를 켜 두면 그만큼 어려운 문항을 더 출제해 상·중·하는 목표 비율에 가깝게 맞추고, 출력할 때 '최종 문항 자동 선정'이 판정 난이도로 비율을 맞춥니다. 최상은 아직 목표만큼 나오지 않아 담당자와 기준을 협의하고 있습니다.

원고가 수정되었습니다. 문항을 다시 만들어야 하나요?

아닙니다. 원고 등록 화면에서 '새 판으로 교체'를 하면 쪽수는 자동으로 따라가고, 근거 문장이 바뀐 문항만 표시됩니다(AI 사용 없음). 원고가 더 바뀌지 않을 때 '변경 문항 일괄 처리'를 한 번 누르면 됩니다. 원고가 여러 번 바뀌어도 AI는 마지막에 한 번만 씁니다.

실수로 문항을 지우거나 프로젝트를 망쳤습니다.

출제가 끝날 때, 원고를 교체하기 전, 프로젝트를 삭제하기 전에 자동 백업됩니다(프로젝트마다 최근 10개). 프로젝트 관리 → 백업에서 그 시점으로 되돌립니다. 되돌리기 전 상태도 자동으로 백업됩니다.

9담당자와 결정이 필요한 사항

항목현재 설정(임시)
차시 나누는 기준실제 원고는 절 단위 5차시로 임시 지정. 소절 단위(21개)일 수도 있음
학습목표원고에 없어 머리말·목차로 임시 작성. 공식 학습목표가 있으면 교체
출제 제외 범위표지·머리말·목차, 부록·참고문헌 제외. 부록의 점검표·용어집을 출제할지
난이도·유형 기본 비율최상 5 · 상 15 · 중 60 · 하 20 / 선다 50 · 진위 30 · 단답 20. (협의 반영) 선다형 옳지 않은 것 : 옳은 것 = 8 : 2, 최상 = 자격시험 수준 실무 사례형
최상 기준·난이도 정의받은 기준 문서에는 비율만 있어 지금은 블룸 인지 수준에 맞춘 임시 기준안을 씁니다(관리 → 난이도 기준에서 담당자가 고치고 확정). 자격시험형 실무 사례 문항을 만들어도 AI 검수는 대부분 '상'으로 판정합니다("진술마다 원고 표의 한 칸과 대응하면 풀린다"). 상·중·하는 난이도 보정 출제로 맞추지만, 최상은 300문항 기준 목표 15문항 중 약 4문항만 예상됩니다. '자격시험형 사례 문항이면 최상으로 본다'로 기준을 정할지, 실제 문항을 보고 결정 필요(Codex 교차 판정: 우리 AI 검수와 76% 일치, 최상 경계는 우리 검수가 조금 엄격)
단답형난이도는 하·중만 배정. 허용 답안(동의어·영문 표기) 인정 범위
문항 번호 · NCS 열양식 연번 사용, NCS 열(N~P)은 비움
태도·원칙 중심 과정의 변별력"과신하지 말고 확인하라"류 내용은 오답이 상식으로 걸러지기 쉬움. 허용 수준 결정 필요
최신성(시의성) 확인지금은 원고만 기준으로 검증하고 외부 확인은 하지 않음. 기관명·법령·금액 기준·전화번호·날짜가 든 문항에 '시의성 확인' 표시만 붙임. 웹 검색으로 최신 여부를 확인할지, 원고와 현재 사실이 다를 때 무엇을 기준으로 할지 결정 필요
LLM 사용 방식(협의 반영) 앞으로 1~2개월은 Claude 구독으로 출제(새 설치 기본값). 서비스 운영 시 API 키·사내 LiteLLM 중 선택. 300문항 출제는 약 3시간 40분(난이도 보정 포함 추정)·AI 호출 약 1,500회 이상
사내 LiteLLM연결 기능은 있으나 실제 서버로는 시험 전. 주소·API 키·사용 가능 모델 목록을 받으면 연결 확인 → 시험 출제로 품질 비교
딥시크(DeepSeek) 사용기술적으로 연결 가능(LiteLLM과 같은 방식). 공식 API는 원고가 해외(중국) 서버로 전송되므로 보안 정책 확인 필요. 사내 설치형이면 외부 전송 없음. 허용되면 같은 조건으로 출제해 Claude·Codex와 비교(평가는 다른 AI가 검수)
원고의 외부 전송출제 시 해당 쪽 원문이 AI 서비스로 전송됨. 어떤 서비스(Claude·Codex·LiteLLM·딥시크)까지 허용할지 결정 필요
이의신청 대응서비스 시스템에 문항을 올릴 때 문항키(엑셀 숨김 R열)를 함께 보관할 수 있는지. 보관하면 조회가 가장 빠름
서버형 전환당분간 로컬 설치형(휴대용 패키지). 서버형·여러 과정 통합 문항 은행은 2차 범위

10설치·데이터 이전·백업

  • 설치: '출제도구_휴대용_날짜.zip'을 짧은 경로(예: D:\출제도구)에 풀고 run.bat을 두 번 클릭합니다. Python을 따로 설치할 필요가 없습니다. 처음 한 번 Claude_로그인.bat으로 회사 Claude 계정에 로그인합니다.
  • 업데이트: 프로그램만 바뀌면 '출제도구_프로그램만_날짜.zip'을 설치 폴더에 덮어씁니다. 출제 데이터(projects)와 백업은 그대로 남습니다.
  • 다른 PC로 옮기기: 데이터_내보내기.bat → ZIP → 새 PC에서 데이터_가져오기.bat. 두 PC에서 동시에 같은 과정을 고치지 않습니다(문항 DB는 합쳐지지 않음).
  • 백업: 프로그램 폴더의 '백업'에 프로젝트별 최근 10개가 자동으로 남습니다.
